# Déploiement GitHub Pages – à faire une seule fois

Tu vois une 404 sur `main.jsx` parce que GitHub sert le **code source** (fichiers du dépôt) au lieu du **site compilé**. Il faut lui faire servir la branche **gh-pages**, qui ne contient que le build.

---

## 1. Lancer le workflow une première fois

1. **Push** ce dépôt sur **main** (ou **master**).
2. Va sur GitHub → onglet **Actions**.
3. Clique sur **Deploy to GitHub Pages** → **Run workflow** (bouton vert) → **Run workflow**.
4. Attends que le job soit **vert** (1–2 min).  
   → La branche **gh-pages** est créée avec le site compilé.

---

## 2. Configurer Pages pour utiliser gh-pages

1. Toujours sur GitHub : **Settings** (Paramètres du dépôt).
2. Menu de gauche → **Pages**.
3. Dans **Build and deployment** :
   - **Source** : **Deploy from a branch**
   - **Branch** : choisis **gh-pages** (pas main).
   - **Folder** : **/ (root)**  
4. **Save**.

---

## 3. Vérifier

- Attends 1–2 minutes.
- Ouvre : **https://blandinebalde.github.io/hangul-learn/**

Le site doit s’afficher sans erreur. La branche **gh-pages** ne contient que le build (index.html + assets/), donc plus de 404 sur `main.jsx`.

---

## Si le workflow est en erreur (rouge)

- Ouvre le run en rouge → clique sur le job **deploy**.
- Regarde quelle étape échoue :
  - **Install dependencies** : vérifie que `package-lock.json` est bien dans le dépôt.
  - **Build** : vérifie qu’il n’y a pas d’erreur dans le code (tu peux lancer `npm run build` en local).
